### Projekty

**[portfolio-dashboard](https://github.com/SiatkowskiKamil/portfolio-dashboard)** — raport
kondycji portfela projektów czytający dane z Jira Cloud. **Wdrożony i używany w firmie.**
Zastąpił stronę w Confluence aktualizowaną ręcznie co miesiąc: te same wskaźniki, te same
definicje, liczone na nowo przy każdym otwarciu. Czysty HTML, CSS i JavaScript — bez
frameworka, bez kroku budowania, bez zależności, bo musiał działać na zablokowanej
maszynie firmowej i dać się przekazać następnej osobie. Dwa języki, filtrowanie i
sortowanie wszystkich tabel, wgrywanie danych przez sam raport. Tutaj w publicznej,
w pełni zanonimizowanej wersji z danymi demonstracyjnymi.

**[ecommerce-sales-analysis](https://github.com/SiatkowskiKamil/ecommerce-sales-analysis)** —
analiza rocznych danych sprzedaży w pandas: trendy, sezonowość, najlepsze produkty,
wnioski dla marketingu. Projekt końcowy kursu.

**[stores-rest-api](https://github.com/SiatkowskiKamil/stores-rest-api)** — REST API we
Flasku: JWT z unieważnianiem tokenów, SQLAlchemy z migracjami, kolejka zadań, Docker.
Mój pierwszy projekt backendowy, z kursu.

### Czego się trzymam

Raport ma mówić, czego nie wie. Każda liczba, która czegoś nie obejmuje, dostaje obok
zdanie wyjaśniające — brakujące dane pokazuję jako kreskę i liczę osobno, zamiast po
cichu podstawiać wartość zastępczą. Najdroższe błędy w raportowaniu to nie te widoczne,
tylko te, których nikt nie zauważył.

Przy dashboardzie dwie rzeczy w danych okazały się nie tym, czym się wydawały: pole
opisane jako prognoza trzyletnia trzymało pięcioletnią, a arkusz z nagłówkami „(PLN)"
podawał tysiące. Obie wyszły dopiero przy porównaniu sum z liczbami z poprzedniego
raportu — i to jest powód, dla którego każdą zmianę kończę sprawdzeniem, a nie
założeniem.
